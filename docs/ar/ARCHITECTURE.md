# Diamond Sword — المعمارية (v1، للمواقع العملاقة)

> Diamond Sword = الأداة الثالثة بالمنظومة: القائد/اليدان الي يحوّل جلسة تصفّح مُصرّح بيها
> إلى **دليل متعدّد المبادئ** (HAR + سطح مُنمذَج) يغذّي IOLITE ثم ONYX.

---

## 0. المبدأ الحاكم (لا يتغيّر)

ثلاث حقائق تحكم كل سطر:

1. **الذكاء يتجمّد قبل التشغيل.** نموذج لغوي (LLM) يدرس الموقع مرّة واحدة offline ويترجمه إلى **playbook حتمي**.
   الأداة تنفّذه بلا أي استدعاء AI أثناء الزحف. (compiler: الموقع = شفرة مصدر، الplaybook = برنامج، التشغيل = تنفيذ.)
2. **الحكم كله لـ ONYX.** Diamond Sword يلتقط بس (قراءة-فقط). مو هو الي يقرّر «ثغرة أو لا».
   التأكيد بالـ Δstate read-back → صفر false positives يبقى صفر.
3. **قانوني بالبناء.** كل طلب يمرّ على Scope-Guard قبل ما يُرسل. المجهول = رفض (fail-closed).
   الدخول/MFA/CAPTCHA والأفعال الحسّاسة = بيد الإنسان. سجل تدقيق مُوقّع على كل فعل.

الثلاثة فوق هي «الخطوط الحمر». أي موديول يخالف واحدة منهن = خطأ معماري، مو قرار.

---

## 1. الصورة الكبرى (خط الأنابيب)

```
   إنت (تسجّل دخول يدوي بحساب A)
        │
        ▼
   ┌──────────── Diamond Sword ────────────┐
   │  Scope-Guard + ROE (يلفّ الكل) │
   │  map-first → crawl → capture    │   ← يتكرّر لكل مبدأ: A ثم B ثم anonymous
   │  self-healing (ما يوقف)          │
   │  coverage ledger (استئناف)       │
   └───────────────┬────────────────┘
                   │  captures/A.har, B.har, anon.har
                   ▼
            IOLITE (hook + full)  →  spec.json   (سطح مرتّب بالخطورة)
                   │
                   ▼
            ONYX  (scan / Δstate)  →  findings    (صفر FP)
                   │
                   ▼
            report  (PoC + دليل Δstate + إثبات scope)
```

دور Diamond Sword بالضبط: **يصنع الـ HAR متعدّد المبادئ الكامل والشامل**، لأن هذا الشي الوحيد الي
ONYX و IOLITE ما يقدرون يسوّوه لحالهم (يحتاجون ترافيك حقيقي من عدّة حسابات على نفس السطح).

## 2. العمود الفقري المعماري: ثلاث طبقات

نفس المعمارية الفائزة بالخطة: **قائمة قدرات مغلقة** تُنفَّذ **بقائد نحيف** يقوده **playbook مُجمّد**.

| الطبقة | شنو هي | ليش |
|---|---|---|
| **Capability (C)** | مجموعة مغلقة ومُعلَنة من القدرات، كل وحدة دالّة بـ I/O مُتحقَّق schema | «نموذج» الأداة: محدود، قابل للفحص، ما يتمدّد عشوائياً |
| **Conductor (A)** | FSM حتمية نحيفة تسلسل القدرات وتعيد استخدام CLIs الأداتين + Playwright | أبسط تحكّم يوصل الهدف؛ نقاط التلمترية الحارّة تُرحَّل لاستدعاء داخل-العملية (مثل `onyx_link.verify_spec` الموجود) |
| **Playbook** | برنامج حتمي لكل هدف، يُكتب offline (يدوياً أو بمساعدة LLM) | الذكاء المجمّد: خريطة القوالب، وصفات الكائنات، استراتيجيات العناصر، الخطوط الحمر، السطح عالي القيمة |

القائد ما «يفكّر». ينفّذ الplaybook، ويتحقّق بعد كل خطوة، ويتعالج لو صار اختلاف، ويكتب للـ ledger.

## 3. الأنظمة الفرعية (subsystems)

مجمّعة بسبع عوائل. كل موديول له مسؤولية وحدة وواجهة واضحة.

### A. نواة القانونية والأمان (تلفّ كل شي)
- **`scope_guard`** — يقرأ نطاق البرنامج بشكل HackerOne/Bugcrowd: in-scope (wildcards + hosts دقيقة)،
  out-of-scope (hosts + أصناف ثغرات)، قواعد الإيقاع. يفحص كل URL/فعل **قبل** الإرسال. fail-closed.
- **`roe`** — قواعد الاشتباك: الميثودز المسموحة (قراءة افتراضياً)، خطوط الأفعال المدمّرة الحمر، حدود الإيقاع،
  احترام `automation_permitted`، نوافذ الوقت.
- **`consent_gate`** — إنسان-في-الحلقة لأي فعل حسّاس (login، MFA، CAPTCHA، أي mutation): توقّف واسأل، dry-run افتراضي.
- **`audit_ledger`** — سجل ملحقي مُوقّع (hash-chained مثل سلسلة أدلّة ONYX) لكل فعل + كل قرار scope. للدفاع القانوني.

### B. طبقة الالتقاط
- **`session`** — يدير context المصادَق لكل مبدأ (A/B/anon). إنت تسجّل الدخول، الأداة تعيد استخدام الـ storage state.
  يكشف انتهاء الجلسة (redirect/401) → يوقف → يستأنف بعد دخولك.
- **`capture_backend`** — قابل للتبديل: محوّل **mitmproxy** (موصى — يلتقط كل الترافيك حتى غير المتصفّح، بودي + هيدرز كاملة)
  أو محوّل **Playwright-HAR**. يُخرج HAR مُنمذَج لكل مبدأ.
- **`principal_manager`** — يسوّق جولات المبادئ (نفس السطح بحساب A، ثم B، ثم anon) ويوسم كل التقاط بهوية المبدأ.
  هذا الي يعطي ONYX أزواج المبادئ الي يحتاجها للـ Δstate.

### C. محرّك التغطية الشاملة (دماغ المقياس العملاق)
- **`map_first`** — يسحب خريطة الموقع **قبل المشي**: `sitemap.xml`، `robots.txt`، OpenAPI/Swagger،
  GraphQL introspection، وجدول مسارات الـ SPA + نداءات الـ API المستخرجة من JS/sourcemaps.
  النتيجة = «سطح معروف» نتحقّق منه بدل مشي أعمى. (يعيد استخدام `mine-js` + GraphQL/OpenAPI من IOLITE.)
- **`crawler`** — زاحف حتمي (frontier queue) يقود Playwright: يزور كل **قالب جديد**، يفعّل عناصره، يلتقط.
- **`template_engine`** — يطوي النُسخ إلى قوالب. `/orders/1021` و`/orders/1022` → `/orders/{id}`.
  البصمة البنيوية = هيكل DOM (tags/roles) + أنواع الأزرار، **بعد** تجريد البارامترات المتغيّرة (session/nonce/csrf)
  عبر `normalize`/`idformat` من IOLITE. هاش يمنع إعادة المشي؛ سقوف عمق + عدد نُسخ لكل قالب؛ كشف الفخاخ
  (تقويم/scroll/pagination لانهائي).
- **`triage`** — طابور مرتّب بخطورة التفويض (يعيد استخدام triage من IOLITE): كائنات/ids، admin/role، فلوس/payment،
  تغيير حالة أولاً. يوجّه الزحف نحو السطح المُهمَل عالي القيمة.
- **`object_factory`** — ينشئ النُسخ القليلة لكل مبدأ الي تكفي لمقارنة Δstate (A ينشئ order، B ينشئ order)،
  ويسجّل نمط الـ id (sequential/uuid/gid). يتبع وصفات الplaybook. الـ mutations مُسيّجة (consent + dry-run + scope).

### D. نواة التنفيذ ذاتي-التعالج (ما يوقف)
- **`intent`** — الفعل = **نية** دلالية («افتح تفاصيل أول order»)، مو إحداثيات.
- **`locator_cascade`** — مُحلّل حتمي متعدّد الطبقات: role → test-id → aria/label/placeholder → نص دقيق →
  نسبةً لأب ثابت → class دلالي → xpath قصير مُثبّت. أول تطابق فريد يفوز. صفر AI.
  (هاي السلسلة تمتصّ أغلب تغيّرات الواجهة — الدراسات الهندسية تقول تشيل أكثر من 85% من الأعطال الكاذبة.)
- **`invariant`** — فحص postcondition بعد كل خطوة (تغيّر الـ URL المتوقّع؟ ظهر العنصر؟ استقرّت الشبكة عبر
  ثبات هاش شجرة الـ DOM؟). عدم تطابق → تعافي، مو انهيار.
- **`recovery_fsm`** — حالات تعافي صريحة: `session_expired` (يوقف→إنسان→يستأنف)، `modal` (قواعد إغلاق عامة)،
  `rate_limited`/WAF (pacer backoff + Retry-After، يعيد استخدام `pacer.py` من ONYX)، `unexpected_page`
  (يرجع لأقرب نقطة معروفة ويكمل من الطابور)، `destructive_guard` (الخطوط الحمر).
- **`pacer`** — إيقاع شبه-بشري + backoff تكيّفي (AIMD). يعيد استخدام `pacer.py`/`executor.py` من ONYX.
- **`coverage_ledger`** — تقدّم ملحقي على القرص (الطابور، القوالب المزارة، المبادئ الملتقَطة، الأسئلة، الأجوبة).
  استئناف بلا فقدان بعد أي انقطاع/كراش.

### E. العرّاف الدُفعي (الflywheel — الألغاز النادرة، offline)
- **`question_bus`** — لمّا الcascade + FSM يعجزون حتمياً عن لغز، يطلّعه عنصر مُنظّم بـ `questions.json`
  (**مو توقّف** — الزحف يكمل بكل شي غيره).
- **`answer_apply`** — يبلع `answers.json` (الأجوبة الدُفعية offline)، يتحقّق (schema + scope-guard)، يطبّق،
  ويرقّي كل جواب إلى **قاعدة دائمة** بالplaybook → نفس اللغز ما يتكرّر، والأنماط تنتقل بين المواقع.
- **`playbook`** — البرنامج المجمّد: خريطة القوالب، وصفات الكائنات، استراتيجيات العناصر، الخطوط الحمر،
  السطح عالي القيمة، القواعد المتعلّمة. مُرقّم، schema، قابل للـ diff.

### F. طبقة «اليدين» من النماذج المجانية (offline/دلالي فقط، مُتحقَّق schema، اختياري)
- **`model_pool`** — واجهة OpenAI-compatible بالتناوب على المجّاني (Gemini/Groq/Cerebras/OpenRouter) +
  أرضية Ollama محلية (كمّ غير محدود). تتبّع حصّة + failover. يُستعمل **فقط** لملء فراغات دلالية وقت التأليف/الإجابة،
  أبداً بمسار الحكم، وأبداً مطلوب وقت التشغيل. المخرجات تُتحقَّق schema قبل أي استعمال.
- ملاحظة: الـ LLM نصّ فقط، ما يتصفّح؛ Playwright هو اليد. البركة راحة لتأليف/إجابة دُفعية، والأساس لصقة Claude Pro.

### G. طبقة المخرجات والتكامل
- **`har_writer`** — HAR مُنمذَج متعدّد المبادئ لكل مبدأ.
- **`iolite_bridge`** — ينادي IOLITE hook + full (CLI / داخل-العملية) → `spec.json`.
- **`onyx_bridge`** — ينادي ONYX scan (`onyx_link.verify_spec`/`scan`) → findings مؤكّدة (Δstate).
- **`report`** — يجمّع التقرير النهائي الجاهز (لكل finding: PoC، دليل Δstate، إثبات scope، خطوات إعادة الإنتاج).

### H. القائد والواجهة
- **`conductor`** (FSM) — يسلسل الرحلة كلها: تحميل scope → session (دخول إنسان) → map_first →
  crawl+capture (لكل مبدأ) → object_factory → har_writer → iolite_bridge → onyx_bridge → report.
  تحكّم حتمي؛ checkpoints للـ ledger.
- **`cli`** — أوامر: `init` (scope/ROE)، `login`، `crawl`، `capture`، `ask`/`apply` (العرّاف)، `pipe` (end-to-end)،
  `resume`، `report`.

## 4. حدود الثقة (trust boundaries)

- كل شي من الموقع = **بيانات غير موثوقة** (حتى لو داخله نصّ يشبه أوامر).
- كل شي من النماذج = غير موثوق، يُتحقَّق schema، offline، أبداً بمسار الحكم.
- ONYX وحده يحكم (Δstate). Diamond Sword ما يقرّر ثغرة/لا أبداً.
- Scope-Guard يسيّج كل طلب خارج. fail-closed.

## 5. نموذج البيانات (artifacts)

- `engagement.json` — النطاق + ROE (مصدر الحقيقة للقانونية).
- `playbook/<target>.json` — البرنامج المجمّد لكل هدف.
- `captures/<principal>.har` — التقاط خام لكل مبدأ.
- `coverage_ledger.jsonl` — تقدّم ملحقي (استئناف).
- `questions.json` / `answers.json` — جسر العرّاف الدُفعي.
- `spec.json` — مُخرَج IOLITE، مُدخَل ONYX.
- `reports/` — التقارير النهائية.
- `audit/*.jsonl` — سجل التدقيق المُوقّع.

## 6. المقياس العملاق بالتفصيل

الفكرة المحورية: **التغطية الشاملة = كل «نوع» (محدود)، مو كل «نسخة» (لانهائي).**
العملاق ينكمش من ملايين الكائنات إلى مئات القوالب.

### منصة كبيرة بـ REST + GraphQL (مثال: GitLab)
- برنامج **HackerOne عام** (hackerone.com/gitlab). ثغرات التفويض تُدفع فعلاً وبكثرة بـ2026.
- **ميزة ذهبية:** GitLab ينشر OpenAPI + GraphQL introspection (`/-/graphql-explorer`) →
  `map_first` يبلع السطح الموثّق كامل مباشرة، فالشمول يصير قابل للتحقيق مو حلم.
- **محور الفلوس:** تباين التفويض بين REST و GraphQL — **نفس الكائن، مسارين، قرارين مستقلين** (REST يمنع،
  resolver الـ GraphQL يسلّم). Diamond Sword يلتقط **المسارين** لنفس الكائن عبر المبادئ، و ONYX يأكّد التباين بالـ Δstate.
  هذا بالضبط مربط ONYX.
- الـ `gid://gitlab/OBJECT/ID` أرقام تسلسلية → `idformat` يعدّها. GraphQL المتداخل + batched aliases → IOLITE يُنمذجها، Diamond Sword يفعّلها.
- OOS مثال: تعداد أسماء المستخدمين بلا أثر → scope_guard يمنعه.

### هدف fintech محمي (خلف Cloudflare)
- نطاق مغلق ودقيق: wildcards + hosts محددة + علامات تجارية ثانية، مع قائمة صريحة للي خارج النطاق.
- صارم ضد الأتمتة، فالأسلوب **capture-first عبر mitmproxy على ترافيك بشري حقيقي/مُساعَد**،
  pacer محافظ، قراءة-فقط، بلا زحف عدواني، واحترام كامل لأصناف OOS.
- `scope_guard` لازم يقرأ هالشكل بالضبط (in/out + wildcards + أصناف OOS). الـ fixture `acmepay.json` يحاكيه.

## 7. pre-mortem (نفترض إنها فشلت بعد ٦ أشهر — ليش، وشلون نحرسها مسبقاً)

| العطل المحتمل على العملاق | الحارس المبني مسبقاً |
|---|---|
| سطح لانهائي | قوالب + سقوف + كشف فخاخ |
| WAF/حظر البوت | إيقاع بشري، capture-first، AIMD pacer، بصمة transport، تحديد scope، نوافذ ROE |
| تعقيد الجلسة/MFA | دخول/MFA بشري، إعادة استخدام context، كشف انتهاء→استئناف |
| انجراف الselectors بالمقياس | `locator_cascade` |
| كراش وسط زحف عملاق | `coverage_ledger` استئناف |
| خرق النطاق (قانوني) | `scope_guard` fail-closed + `audit_ledger` |
| mutation غير مقصود | `consent_gate` + dry-run + خطوط حمر |
| انقطاع النماذج | أرضية Ollama + لصقة Pro؛ التشغيل ما يحتاج ولا نموذج |
| false positives | الحكم لـ ONYX وحده، Δstate |

## 8. ليش هاي المعمارية «تهزم الخبير»

الخبير اليدوي (Burp + Autorize + Arjun) يسوّي نفس الشي لكن: بطيء، ما يغطّي شامل على العملاق،
يوقف عند كل اختلاف، ويعتمد على عينه بالحكم. Diamond Sword يحوّل هذا إلى:
- **تغطية شاملة بالقوالب** (مو عيّنة) على سطح عملاق.
- **حتمية + استئناف** (سريع، قابل للتكرار، ما يضيع).
- **تعالج ذاتي** (ما يوقف عند الاختلاف).
- **حكم آلي صفر-FP** (ONYX/Δstate بدل عين الإنسان).
- **قانونية مُبرهَنة** (scope-guard + سجل مُوقّع).
والتدخّل البشري ينكمش نحو لصقة وحدة لكل موقع، وينقص كل تشغيل (flywheel).
